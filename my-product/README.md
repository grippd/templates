# Example: a repo after grippd has run

This folder shows what a product's repo should look like once grippd is set up. It's the target the compiler is built towards, not real output: grippd doesn't exist yet. The layout is Austin's `platform-template` monorepo (Bun workspaces, SvelteKit web, a jobs Worker, Astro docs, a Drizzle database package), run by Turborepo. grippd sits on top of Turborepo: Turborepo owns the task graph and build cache, and grippd adds the infrastructure, the keys and the deploys.

The product is called `my-product`. It has three apps (web, worker, docs), one Postgres database and file storage.

## Three kinds of file

| Mark | Meaning |
| --- | --- |
| **You write** | Your code, `grippd.yaml`, and ordinary build config (`package.json`, `turbo.json`). Nothing else about infrastructure |
| **Generated** | Compiled from `grippd.yaml` by the grippd GitHub App and committed. Starts with "generated by grippd", collapsed in pull request diffs, and CI fails if anyone edits one |
| **Not in the repo** | Lives only in grippd's cloud: the OpenTofu for every environment and its state, keys, backups, the audit log. The team sees it as a summary in grippd's product terms (`grippd show`, and on every pull request) |

```
grippd.yaml                          You write: the only infrastructure file
package.json                         You write: Bun workspaces; scripts call turbo
turbo.json                           You write: the task graph (build, check, lint, test, dev)
.gitignore                           You write
apps/
  web/        src/ package.json      You write: SvelteKit app
              wrangler.jsonc         Generated: every binding in every environment
  worker/     src/ package.json      You write: cron and Durable Object
              wrangler.jsonc         Generated
  docs/       src/ package.json      You write: Astro site
              wrangler.jsonc         Generated
packages/
  db/         schema, migrations     You write: Drizzle
  storage/                           You write
.github/
  workflows/grippd-checks.yml        Generated: generated files untouched, format, then turbo runs types, lint, tests and build for affected packages
  workflows/grippd-ship.yml          Generated: on main, builds the apps turbo says are affected and uploads them to grippd
  grippd/mint.sh                     Generated: swaps GitHub OIDC for an upload or cache key minted for one job
  grippd/ship.sh                     Generated: bundles and uploads builds, then hands the commit to grippd
  actionlint.yaml                    Generated: knows the Blacksmith runner label
.gitattributes                       Generated: marks the generated files
grippd.lock                          Generated: checksums of every generated file
.grippd/                             Not committed: written by grippd dev each time it starts (the local compose file), and ignores itself
```

## What to notice

- **grippd sits on top of Turborepo.** The team owns `turbo.json`, which says how each package is built and checked. grippd uses Turborepo in three ways:
  - **Affected apps:** `turbo ls --affected` decides which apps a push builds and ships, replacing hand-kept path lists. A change in `packages/db` ships web, worker and migrations; a change in `apps/docs` ships only docs.
  - **CI checks:** `turbo run ... --affected` runs the checks for only the packages a change touches.
  - **Remote cache:** grippd hosts Turborepo's remote cache (`TURBO_API`). Each job's cache token and artifact-signing key are minted per job by `mint.sh`, like every other key. The ship job rebuilds from the cache the checks job filled, and developers' laptops share the same cache.

- **No secret anywhere.** No `.env`, no CI secrets, no keys in Wrangler files. CI mints only upload and cache keys (`mint.sh`); the apps get theirs at run time through the `GRIPPD` binding; the database roles are minted by the lease engine and never written to OpenTofu state (the `ephemeral` blocks).
- **No infrastructure code in the repo at all.** There's no OpenTofu here. It lives in grippd's cloud next to its state, and the team sees what grippd runs in product terms instead:

  ```
  $ grippd show
  - grippd Compute: web (SvelteKit app), worker (Worker, with JobRunner) and docs (static site).
  - grippd Postgres: one database per environment, used by web and worker, each with its own role. ...
  - grippd Cache, grippd Storage, grippd Monitor, grippd Backups, grippd Keys ...
  ```

  The full output is `grippd/fixtures/my-product/summary.md`.
- **No caching code.** `apps/web/src/lib/server/items.ts` is a plain query. Every cache layer comes from `database: postgres`.
- **Every infrastructure action runs in grippd's cloud, not in GitHub Actions.** CI checks, builds and uploads (`grippd-ship.yml`). grippd then does the rest in order:
  1. applies the OpenTofu
  2. runs migrations
  3. deploys to staging
  4. checks `/healthz`, and rolls back if it fails

  A `v*` tag promotes the same builds to production; grippd sees the tag itself.
- **Each app has its own keys in each environment:** web and worker each get their own database role, and migrations get a role that exists only while they run.
- **Backups aren't a workflow.** grippd Backups writes them nightly and restore-tests them weekly.
- **`/healthz` stays open** behind the team-only sign-in, so grippd Monitor can reach it, and the worker's cron has a heartbeat.

## How faithful it is

- The JSON, YAML and shell files parse, the workflows pass `actionlint` and the scripts pass `shellcheck`, and `shasum -a 256 -c grippd.lock` passes.
- The OpenTofu grippd keeps for this repo (`grippd/fixtures/my-product/cloud/`) is a sketch: resource names and fields haven't been checked against each supplier's current schema, and the `grippd` provider and `grippd-keys` service don't exist yet.
- `api.grippd.sh`, the hostnames and every ID are placeholders.

The generated files are produced by grippd's real compiler (`grippd/packages/compiler`), and `grippd/fixtures/my-product/repo` is the golden copy of this repo that the compiler is tested against. To regenerate, run `bun run grippd build ../example` from `grippd/`, or `bun run grippd check ../example` to verify. `_previews/example/make_example.py` wrote the first version and is retired.
